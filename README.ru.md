# Agent Deck

[![Статус CI](https://github.com/xonika9/agent-stream-deck/actions/workflows/ci.yml/badge.svg)](https://github.com/xonika9/agent-stream-deck/actions/workflows/ci.yml)

Agent Deck объединяет задачи Codex, OpenCode и T3 Code на Elgato Stream Deck. На macOS шесть динамических клавиш показывают задачи одного источника или всех трёх; на Windows сохраняется локальная интеграция с Codex. Для Codex доступны встроенные команды Micro: выбор задачи, действия, навигация и уровень рассуждений. Клавиши OpenCode и T3 Code показывают состояние задач и выводят приложение на передний план.

Этот репозиторий — форк и продолжение проекта [dazer1234/codex-stream-deck](https://github.com/dazer1234/codex-stream-deck). Текущую разработку и выпуски поддерживает [xonika9](https://github.com/xonika9).

> Полевыми заметками об AI-моделях и инструментах для разработчиков я делюсь в телеграм-канале [«Контролируемые галлюцинации»](https://t.me/+DOZWlhI4r4EyYjgy).

> [!IMPORTANT]
> Это независимый общественный проект. Он не создан, не поддерживается и не одобрен OpenAI или Elgato. Проект использует недокументированные внутренние механизмы настольного Codex, поэтому после обновления Codex ему может потребоваться адаптация.

## Выберите режим

Один и тот же пакет плагина Stream Deck работает на обеих платформах. Установите только тот запускатор и ту конфигурацию, которые нужны для вашего варианта.

| Режим | Приложение Stream Deck | Источники задач | Руководство |
|---|---|---|---|
| Только Windows | Windows | Локальный Codex для Windows | [Настройка Windows](docs/WINDOWS.md) |
| Только Mac | macOS | Локальные Codex, OpenCode, T3 Code | [Настройка macOS](docs/MACOS.md) |

На обеих платформах Codex работает локально. На macOS также доступны локальные задачи OpenCode и T3 Code и задачи удалённых Linux-серверов через сохранённые подключения SSH. Отдельный обмен между экземплярами Codex удалён.

## Источники задач и управление

Выберите общий источник в инспекторе свойств любого действия **Agent** в Stream Deck: `Codex`, `OpenCode`, `T3 Code` или `All`. Режим `All` объединяет все три источника; сохранённый `Both` используется как `All`. Выбор OpenCode, T3 Code или All включает **Active queue**, сохраняя прежнюю настройку очереди для отдельного режима Codex.

| Источник | Подключение | Нажатие на клавишу задачи |
| --- | --- | --- |
| Codex | Локальный запускатор: [macOS](docs/MACOS.md) или [Windows](docs/WINDOWS.md) | Выбирает задачу через встроенную интеграцию Codex. |
| OpenCode | Локальная служба Desktop на macOS или сохранённое подключение SSH: [совместимость](docs/OPENCODE_COMPATIBILITY.md) | Выводит OpenCode Desktop на передний план без выбора конкретного разговора. |
| T3 Code | Отдельное подключение только для чтения к локальному серверу или работающему удалённому Linux-серверу через SSH: [настройка и совместимость](docs/T3CODE_COMPATIBILITY.md) | Выводит T3 Code на передний план без выбора конкретного разговора. |

В OpenCode и T3 Code свежие завершённые задачи и ошибки исчезают из очереди через пять минут, когда источник сообщает о просмотре результата или при нажатии на их клавишу. Новый результат того же разговора может появиться снова. Подтверждение просмотра T3 остаётся локальным для плагина; для OpenCode плагин также пытается сообщить о просмотре через поддерживаемый API.

Подключение T3 выполняется из копии исходников с Node.js 24 или новее и зависимостями, установленными через `npm ci`. Оно создаёт отдельную сессию только для чтения. Следуйте [инструкции подключения](docs/T3CODE_COMPATIBILITY.md) для локального сервера или используйте `npm run connect:t3:ssh -- <ssh-alias>` для удалённого. После настройки установленный плагин собирает задачи самостоятельно. Команды действий Micro, джойстика, энкодера, уровня рассуждений и создания новой задачи относятся к Codex.

## Требования

- Настольное приложение выбранного источника задач; для встроенных команд Codex требуется настольный Codex.
- Elgato Stream Deck 7.1 или новее на компьютере, к которому подключён Stream Deck.
- Node.js 24 или новее для платформенного запускатора.
- Windows 10+ или macOS 13+.
- Ранее проверялся обычный 15-клавишный Stream Deck MK.2. Результаты автоматических проверок, проверки приложений и физического устройства указаны отдельно для каждого выпуска.

Другие модели Stream Deck могут работать, но готовая раскладка и проверка на физическом устройстве ориентированы на стандартный MK.2 с сеткой 5×3.

## Быстрая установка

> [!NOTE]
> Плагин и архивы запускаторов доступны на [странице выпусков](https://github.com/xonika9/agent-stream-deck/releases). Исходники можно собрать командами из раздела [«Сборка и проверка выпуска»](#сборка-и-проверка-выпуска).

1. Скачайте `com.xonika9.codex-deck.streamDeckPlugin` из подходящего выпуска xonika9 и откройте его на компьютере с Stream Deck.
2. Скачайте только запускатор для этого компьютера:
   - Windows: `codex-deck-launcher-windows-vX.Y.Z.zip`
   - macOS: `codex-deck-launcher-macos-vX.Y.Z.zip`
3. Следуйте руководству для [Windows](docs/WINDOWS.md) или [macOS](docs/MACOS.md).
4. Выберите источник задач в инспекторе свойств действия **Agent** в Stream Deck. Для встроенных команд Codex настройте назначения агентов, действия, джойстик и энкодер в **Codex Settings > Codex Micro**.
5. Соберите две страницы Stream Deck, описанные ниже.

В README используется название Agent Deck; имена опубликованных пакетов, UUID плагина и действий и локальные каталоги данных сохраняют прежние идентификаторы Codex Deck.


> [!WARNING]
> Форк xonika9 использует новый UUID плагина `com.xonika9.codex-deck`. Stream Deck считает его отдельным от исходного `com.simeo.codex-deck`: существующие действия, их параметры и общие настройки плагина автоматически не переносятся. Сохраните или экспортируйте профили, не держите обе версии включёнными одновременно, заново соберите обе страницы из новых действий, а затем удалите старый плагин. Локальные данные узлов, старые частные настройки ретранслятора и пользовательские значки остаются в прежнем каталоге; служба-наблюдатель macOS намеренно сохраняет метку `com.simeo.codex-deck.watcher`.

## Возможности

- Шесть динамических клавиш агентов с общим источником `Codex`, `OpenCode`, `T3 Code` или `All`.
- Необязательная общая **Active queue** для всех шести действий агентов на одном компьютере; по умолчанию она выключена.
- Состояния простоя, работы, непрочитанного завершения, запроса подтверждения или ввода, ошибки и пустого слота в реальном времени.
- Светлое и тёмное оформление в стиле Codex со сдержанной анимацией состояний.
- Встроенная обработка нажатия и отпускания для слотов Micro от `ACT06` до `ACT12`.
- Встроенные команды джойстика вверх, вправо, вниз и влево, а также нажатие энкодера.
- Отдельные кнопки повышения и понижения уровня рассуждений с повтором при удержании.
- Управление лимитами в реальном времени: настраиваемая круговая клавиша для пятичасового или недельного окна и обзор двух окон.
- Счётчик кредитов сброса только для чтения; нажатие и удержание не расходуют кредиты.
- Локальное действие `codex://threads/new` для новой задачи.
- Отдельные действия для всех официальных клавиш единичного размера, которые определяются из установленной сборки Codex во время выполнения.
- Необязательная локальная загрузка официальных SVG клавиш; защищённые файлы никогда не входят в репозиторий или выпуски.
- Состояние локального подключения на прежней клавише выбора узла; нажатие обновляет её отображение без выбора другого компьютера.

### Активная очередь

Включите **Active queue** в инспекторе свойств любого действия агента, чтобы собрать актуальные задачи на первых клавишах. Настройка действует сразу для всех действий от **Agent 1** до **Agent 6** на этом компьютере и по умолчанию выключена. Очередь получает задачи из полного встроенного каталога закреплённых и незакреплённых разговоров Codex: сначала идут задачи, требующие внимания, и ошибки, затем завершённые и непрочитанные задачи в прежнем порядке поступления при наличии времени активности, а после них — работающие задачи по времени последнего сообщения пользователя, которое начало работу. Открытие или выбор задачи, изменение заголовка, фоновые рассуждения и вызовы инструментов, ответ ассистента, активность renderer и обычное обновление снимка не меняют порядок работающих клавиш. Новое сообщение пользователя поднимает продолжающую работать задачу.

Для этого порядка Agent Deck читает только тип, временную метку и байтовое смещение структурного события `event_msg` с `payload.type === "user_message"`; текст сообщения не читается. Если событие недоступно — например, плагин запущен заново или запись осталась за пределами последних 512 КиБ файла сессии, — задача получает стабильное место внутри текущей очереди, а не вымышленное время старта. Задачи с известным стартом идут перед задачами без него. Это запасное место действует только в текущем цикле включения очереди: выключение и повторное включение **Active queue** или перезапуск плагина начинает новый цикл, а временно исчезнувшие записи сохраняются 24 часа. Задачи в состоянии простоя или `off` скрываются, остальные позиции сдвигаются без пропусков; на клавиши выводится не больше шести задач.

Если полный каталог временно недоступен или несовместим с текущей версией renderer, **Active queue** безопасно возвращается к существующим шести встроенным слотам Micro, не отключая обычный снимок состояния. Исправная чёрная позиция ничему не назначена и не реагирует на нажатие; сообщения о подключении, ухудшении связи и недоступности узла остаются видимыми.

Если в профиле N клавиш агентов, расположите логические действия **Agent 1** … **Agent N** подряд и по порядку. Пока очередь включена, открыть простаивающие разговоры этими клавишами нельзя. Закреплённые и незакреплённые задачи входят в полный встроенный каталог, а режим **custom** намеренно ограничен шестью назначенными кандидатами, среди которых очередь всё равно может уплотнить релевантные. Выключение **Active queue** полностью восстанавливает прежнюю раскладку источника агентов локального Codex.

## Рекомендуемая раскладка на 15 клавиш

Это готовая двухстраничная раскладка для MK.2. Шесть агентов остаются на главной странице, а менее частые команды навигации и управления рассуждениями вынесены на вторую.

> Это только рекомендация и практичная отправная точка. Любые действия, позиции, страницы и профили можно свободно настроить под свой процесс; Agent Deck не требует именно такой раскладки.

### Страница 1 — агенты и повседневные действия

| Агент 1 | Агент 2 | Агент 3 | Агент 4 | Агент 5 |
|---|---|---|---|---|
| Агент 6 | Действие 1 / Fast | Действие 2 / Approve | Действие 3 / Reject | Действие 4 / Fork |
| Действие 5 / Push-to-talk | Клавиша · Browser¹ | Stream Deck: следующая страница | Нажатие энкодера рассуждений | Новая задача |

Названия действий описывают стандартную настройку Codex Micro. Клавиши всегда следуют актуальным назначениям `ACT06`, `ACT07`, `ACT08`, `ACT09` и `ACT10/11`, выбранным в Codex. ¹Если вы чаще используете `ACT12` / Send, чем Browser, поставьте в эту позицию **Действие 6 / Send**.

### Страница 2 — навигация и рассуждения

| Локальное подключение Codex² | Пусто | Джойстик вверх / Plan | Рассуждения ниже | Рассуждения выше |
|---|---|---|---|---|
| Пусто | Джойстик влево / Back | Stream Deck: предыдущая страница | Джойстик вправо / Forward | Нажатие энкодера рассуждений |
| Stream Deck: сменить профиль³ | Пусто | Джойстик вниз / Sidebar | Пусто | Новая задача |

²Клавиша показывает состояние локального подключения Codex. Её UUID в старых профилях сохраняется; старый выбор удалённого компьютера игнорируется без изменения частных файлов. ³Настройте встроенное действие Stream Deck **Switch Profile**, чтобы вернуться к своему обычному профилю; проект не распространяет идентификаторы пользовательских профилей.

Навигация по страницам и смена профиля — встроенные действия Stream Deck. Все остальные названные команды предоставляет Agent Deck. Каждая официальная клавиша Codex Micro также доступна как отдельное действие, поэтому дополнительные страницы можно настраивать, не меняя шесть синхронизированных слотов действий Micro.

### Лимиты и управление сбросом

![Управление лимитом, обзором и кредитами сброса](docs/assets/usage-controls-preview.svg)

Добавьте **Usage Limit** для кругового отображения использованной квоты: число и заполнение показывают процент расхода. В инспекторе свойств Stream Deck можно выбрать окно **5 hours**, **Weekly** или **Automatic**: автоматический режим предпочитает пять часов и переключается на неделю, если короткое окно недоступно. **Usage Overview** показывает оба окна отдельными полосами использованной квоты; отсутствующее окно обозначается как недоступное. На macOS окна квот берутся из свежего снимка виджета CodexBar и доступны даже при закрытом Codex Desktop; Windows использует прежний источник Codex Desktop.

**Reset Credits (Read Only)** показывает количество кредитов сброса, которое сообщает Codex. UUID прежнего действия сохраняется для существующих профилей. Нажатие и удержание ничего не делают: плагин не расходует кредиты. Клавиши лимитов тоже не выполняют действие при нажатии; отображаемое окно выбирается в настройках.

Лимиты и кредиты сброса берутся из локального источника учётной записи. На Mac окна квот читает CodexBar, а счётчики сброса дополняются из подключённого локального моста Codex. На Windows используется локальный запрос рендерера.

## Официальные SVG клавиш не включены

Публичный исходный код и выпуски намеренно не содержат SVG-файлы официальных клавиш OpenAI Codex Micro. Собственные плитки агентов, индикаторы состояний, свечение, анимации, резервные подписи и графика плагина включены.

Если у вас есть право использовать файлы из собственной установки Codex, скопируйте их вне репозитория в:

```text
Windows: %LOCALAPPDATA%\CodexDeck\icons
macOS:   ~/Library/Application Support/CodexDeck/icons
```

Назовите каждую копию по идентификатору клавиши Codex, например `FAST.svg`, `APPR.svg`, `REJ.svg`, `SPLIT.svg` или `MIC.svg`. По явному указанию не перерисовывать, не скачивать, не отправлять, не публиковать и не коммитить файлы Codex может изучить локальную установку и скопировать точные существующие SVG. Защищённый порядок действий и полный список имён приведены в [руководстве по локальным значкам](docs/ICON_SETUP.md).

## Как это работает

Следующая схема описывает встроенное управление Codex. Для OpenCode и T3 Code работают отдельные сборщики задач; см. [источники задач и управление](#источники-задач-и-управление).

```text
Клавиша Stream Deck
    -> плагин Agent Deck
    -> локальное подключение Chrome DevTools
    -> шина событий хоста рендерера Codex
    -> встроенный обработчик Codex Micro
```

Запускатор включает случайный порт Chrome DevTools, привязанный к `127.0.0.1`. Плагин находит модули рендерера с хешем версии, читает встроенную раскладку и состояние Micro и отправляет те же семейства событий, которые использует интеграция Micro:

- `codex-micro-device-state-changed`
- `codex-micro-hid-event`
- `codex-micro-joystick-event`

Виртуальный драйвер HID не устанавливается, файлы приложения Codex не изменяются. Подробнее см. [архитектуру и безопасность](docs/ARCHITECTURE.md).

## Безопасность и конфиденциальность

- Отладочный адрес Codex привязан к `127.0.0.1`; его нельзя открывать в сеть или перенаправлять.
- CDP предоставляет широкие полномочия: другой недоверенный процесс от имени того же локального пользователя может попытаться получить к нему доступ.
- В Agent Deck нет телеметрии, облачного сервиса и службы обновлений.
- Для Codex Agent Deck читает точные имена локальных файлов rollout, чтобы определить принадлежность, и ограниченный недавний хвост структурных меток состояния вместе с числовыми полями `token_count`. Он не разбирает и не передаёт запросы, ответы, названия проектов и другое содержимое разговоров.
- Необязательные SVG остаются в локальной пользовательской папке значков и никогда не отправляются в сеть.
- Частные токены ретранслятора, локальное состояние узлов, журналы и личные пути исключаются проверкой выпуска.

Не используйте запускатор одновременно с недоверенными локальными программами. См. [SECURITY.md](SECURITY.md).

## Совместимость

Совместимость версионируется с каждым выпуском, поскольку Agent Deck зависит от недокументированных внутренних механизмов настольного Codex. Проверенные сочетания версий и результаты проверки каждого выпуска указаны на [странице выпусков](https://github.com/xonika9/agent-stream-deck/releases).

OpenCode и T3 Code поддерживаются только на macOS и зависят от совместимости их API. См. [совместимость OpenCode](docs/OPENCODE_COMPATIBILITY.md) и [настройку и совместимость T3 Code](docs/T3CODE_COMPATIBILITY.md).

Последняя проверка исходного проекта охватывала путь Windows с физическим устройством и ретранслятор Windows + Mac на реальной конфигурации. Также были проверены запускатор, наблюдатель, встроенный мост и пакет плагина для macOS, но не Stream Deck, физически подключённый к Mac. Это исторические свидетельства проверки, а не строгие минимумы, максимумы или гарантия для последующих сборок Codex.

## Устранение неполадок

Начните с [руководства по устранению неполадок](docs/TROUBLESHOOTING.md). Главное правило: после обновления плагина перезапускайте только плагин или приложение Stream Deck. Наблюдатель macOS никогда не запускает закрытое приложение Codex; после ручного запуска он допускает не более одного защищённого восстановительного перезапуска, а затем включает общую задержку перед следующей попыткой восстановления.

## Сборка и проверка выпуска

```shell
npm ci
npm run lint
npm run check:boundaries
npm run check
npm test
npm run validate
npm run pack
npm run audit:release
```

Команда `npm run release:prepare -- --version X.Y.Z` создаёт локальную папку кандидата в выпуск с пакетом плагина, ZIP запускаторов и контрольными суммами SHA-256. На macOS оба архива запускаторов собираются автоматически. На другой платформе сначала создайте ZIP для macOS на компьютере Mac с помощью `scripts/package-macos-release.sh`, чтобы сохранить исполняемые биты, а затем передайте его через `--mac-archive /path/to/archive.zip`.

Для исправления Stream Deck с четырёхкомпонентной версией задайте `CODEX_DECK_RELEASE_VERSION=X.Y.Z.W` при запуске упаковщика macOS и передайте `--version X.Y.Z.W` команде `npm run release:prepare`. Пакет npm сохранит форму предварительного выпуска, совместимую с SemVer.

Ничего не публикуется автоматически. См. [CONTRIBUTING.md](CONTRIBUTING.md).
