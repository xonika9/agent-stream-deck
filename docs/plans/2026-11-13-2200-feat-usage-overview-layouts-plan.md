# Три вида кнопки Usage Overview - Plan

## Goal Capsule

- **Objective:** на маленьком экране стримдека два лимита на кнопке «Usage Overview» читаются с первого взгляда.
- **Means:** в настройках кнопки появляется список «Layout» с тремя видами: полоски, два кольца рядом, одно кольцо из двух половин (KTD1).
- **Authority:** явные решения пользователя > `AGENTS.md`, `CONTRIBUTING.md` > этот план.
- **Execution profile:** локальные коммиты в `main`, по коммиту на пункт. Без push и релиза.
- **Stop conditions:** вернуть вопрос владельцу, если новый вид потребует менять источники, окна или кнопку «Usage Limit».
- **Finish and ship:** `ce-work` доводит работу до локальных коммитов, приёмки и установки в живой плагин без кликов.

## Product Contract

### Problem Frame

Подписи и числа на полосках «Usage Overview» слишком мелкие: на устройстве «5H» не читается. Круглая кнопка «Usage Limit» читается хорошо, но показывает только один лимит.

### Key Decisions

- **Три вида в одной кнопке, выбор списком.** Governs R1, R4. (session-settled: user-directed — выбрано вместо отдельной кнопки и галочки «полоски вкл/выкл»)
- **Виды «два кольца рядом» и «одно кольцо из двух половин» по одобренному макету.** Числа одного размера и цвета заголовка, без раскраски. Кольца красятся по правилу круглой кнопки: зелёное, при остатке не больше 20% красное. Governs R2, R3. (session-settled: user-approved — варианты 1 и 3 макета)

### Requirements

- R1. В настройках «Usage Overview» есть список «Layout»: «Bars», «Two rings», «Split ring». Он сохраняется в настройках этой кнопки.
- R2. «Two rings»: два кольца рядом, внутри каждого число, под кольцом подпись окна (`5H`, `WK`, `FBL`, `MO`). Слева верхнее окно из настроек, справа нижнее.
- R3. «Split ring»: одно кольцо из двух дуг, левая — верхнее окно, правая — нижнее; два числа в центре через тонкий разделитель, подписи под своими половинами.
- R4. Кнопки без сохранённого вида остаются полосками. Галочка «Show remaining», значок провайдера, источник и выбор окон работают во всех видах. Окно без данных показывает прочерк вместо числа и пустую дорожку.

### Scope Boundaries

- Кнопка «Usage Limit», источники, окна и полоски в виде «Bars» не меняются.

## Planning Contract

### Key Technical Decisions

- **KTD1. Настройка `overviewLayout: "bars" | "rings" | "split"`** в `UsageKeySettings` (`src/usage/usage.ts`). Всё, кроме `rings` и `split`, разбирается как `bars`. Контроллер передаёт значение в `renderUsageOverviewKey` (`src/stream-deck/render.ts`). Отрисовка повторяет геометрию одобренного макета: кольца радиусом 24 и толщиной 6 в центрах (40,70) и (104,70), числа 21 пт на высоте 78, подписи 12 пт на 116; половины кольца радиусом 40 и толщиной 7 вокруг (72,70) с зазорами 6° сверху и снизу, числа 20 пт в (57,78) и (87,78), подписи 11 пт в (44,128) и (100,128). Значок провайдера в обоих видах стоит там же, где на полосках (23,11, размер 16).
- **KTD2. Без вложенных `<svg>`.** Stream Deck не рисует вложенные `<svg>`, поэтому вся разметка — группы и пути, как у значков (`f729b0b`).
- **KTD3. Инспектор как у соседних полей.** Список сохраняется через `setSettings` с UUID инспектора, остальные поля не теряются (`77463ca`).

## Implementation Units

### U1. Настройка и отрисовка видов

- **Goal:** R2, R3, R4.
- **Files:** `src/usage/usage.ts`, `src/stream-deck/render.ts`, `src/stream-deck/controller.ts`; тесты `test/usage.test.ts`, при необходимости `test/controller.test.ts`.
- **Test scenarios:**
  - `parseUsageSettings` даёт `bars` без поля и при неизвестном значении, `rings` и `split` при них;
  - «Two rings» содержит два кольца с числами верхнего и нижнего окна и обе подписи; «Split ring» — две дуги, оба числа и обе подписи;
  - с «Show remaining» числа и заполнение показывают остаток;
  - окно без данных даёт прочерк и пустую дорожку;
  - при остатке 15% кольцо или дуга красные, при 66% зелёные; числа всегда цвета заголовка;
  - значок провайдера присутствует, вложенных `<svg>` нет;
  - контроллер передаёт вид из настроек кнопки.
- **Verification:** `npm test`, `npm run check`, `npm run lint`, `npm run check:boundaries`.

### U2. Список в инспекторе и документация

- **Goal:** R1.
- **Files:** `static/property-inspector/usage-overview.html`, `test/usage-settings.test.ts`, `README.md`, `README.ru.md`.
- **Test scenarios:** список отражает сохранённый вид, а без поля показывает «Bars» и ничего не записывает; смена вида отправляет `setSettings` с контекстом инспектора и сохраняет остальные поля.
- **Verification:** `npx tsx --test test/usage-settings.test.ts`, `npx tsx --test test/release-docs.test.ts`, `npm test`.
