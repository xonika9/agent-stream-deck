### Исправленные замечания (история)

Это изменения владельца во время обзора, а не автоматическое применение отчётчиком. C1/C2 закрыты и не входят в текущую очередь.

**C1. Проверка комплекта блокирует любой запуск Windows** (исходно P1).

Ручной запуск и установка автозапуска Windows всегда завершаются ошибкой до подключения к Codex; непосредственно запущенный новый наблюдатель также выходит до подтверждения готовности. Команда node -e передаёт путь runtime-override.mjs в process.argv[1], поэтому условие CLI в launcher/runtime-override.ts выполняется, а отсутствующий process.argv[2] вызывает Usage вместо проверки загрузки. Точная команда воспроизведена на текущем собранном комплекте с Node 24; фикстура подменяет runtime строкой import "ws" и потому пропускает этот отказ.

Исходное доказательство: `launcher/Start-CodexDeck.ps1:81 --     & $node.Source --input-type=module -e "await import('node:url').then(m => import(m.pathToFileURL(process.argv[1]).href))" $runtimePath`.

Доказательства закрытия:
- launcher/Start-CodexDeck.ps1:81 -- import(m.pathToFileURL(process.argv[2]).href) codex-deck-preflight $runtimePath
- launcher/Watch-CodexDeck.ps1:164 -- import(m.pathToFileURL(process.argv[2]).href) codex-deck-preflight $runtime
- launcher/runtime-override.ts:4 -- CLI запускается только когда basename(process.argv[1]) равен runtime-override.mjs или runtime-override.ts.
- test/windows-update-fixture.ps1:40 -- настоящий launcher/runtime-override.ts собирается esbuild с external ws, target node24.
- docs/maintenance/evidence/final-owner-validation.json:finalReviewCorrections.windowsPreflight -- redExit1 Usage; greenExit0 реальный runtime импортирован, повреждённый ws отвергнут; Node24.16.0 reviewedHead97095a55 плюс U8.

Валидатор #1 подтвердил закрытие C1/C2 как контекст единственного пробела приёмки; отдельные исторические дефекты не проходили новый пакет независимых проверок. Windows PowerShell 5.1 не проверен.

**C2. Ожидаемое число PowerShell-проверок ломает Windows CI** (исходно P1).

Обязательный npm test на Windows запускает настоящую самопроверку наблюдателя, которая теперь содержит восемь случаев и печатает их количество. Изменённое утверждение ожидает шесть случаев, поэтому успешная самопроверка всё равно приводит к падению теста и Windows-задания CI. На Mac эта проверка пропускается, поэтому локальные 207 успешных тестов не обнаруживают несоответствие.

Исходное доказательство: `test/launcher.test.ts:82 --   assert.match(stdout, /self-test passed \(6 cases\)/i);`.

Доказательства закрытия:
- test/launcher.test.ts:82 -- assert.match(stdout, /self-test passed \(8 cases\)/i);
- launcher/Watch-CodexDeck.ps1:34-41 -- восемь сценариев самопроверки.
- docs/maintenance/evidence/final-owner-validation.json -- PowerShell7.6.6 Mac SelfTest8 exit0, исправлен ожидаемый счётчик; native Windows5.1 ещё не проверен.

Валидатор #1 подтвердил закрытие C1/C2 как контекст единственного пробела приёмки; отдельные исторические дефекты не проходили новый пакет независимых проверок. Windows PowerShell 5.1 не проверен.
