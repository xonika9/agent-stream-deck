# U8: установщик, упаковка и руководства

Изменения выполнены после `97095a55e7ac134455e02364eadc7acf9cf10031` на `main`, без записи Git, целевой установки в приложения, публикации и действий с удалёнными компьютерами. Исходный план и корневой отчёт не менялись.

## Что изменилось

- I1: средство запуска macOS использует собственную переменную `launcher_status`; три ветви выполнены настоящим zsh.
- I2: Windows ждёт освобождения собственного mutex и завершения распознанного прежнего процесса до замены файлов. Таймаут 30 секунд сохраняет сигнал остановки и прерывает обновление до копирования.
- I3: Windows собирает автономный временный комплект из фактических исходных/fallback путей и безопасно импортирует runtime с `ws` на Node.js 24. Этот же проверенный комплект используется установкой и ручным запуском до возможного закрытия Codex; временная копия удаляется в `finally`. Новый watcher проверяет Node.js 24 и реальный runtime, затем пишет отметку со своим PID и одноразовым идентификатором. Установщик принимает только живой новый процесс с соответствующей отметкой. Mac подтверждает PID службы, PID блокировки и свежий идентификатор запуска; изолированный тест реально запускает новый Node watcher, блокирует внешние команды в дочернем процессе и ждёт его завершения/очистки блокировки.
- I4: Windows резервирует общую задержку десять минут до восстановительного перезапуска; смена PID и ошибка запуска её не сбрасывают. Политика нетронутого исходного сеанса сохранена.
- I5: миграция Windows завершает только старый `ssh.exe`, доказанный сохранённым PID, корректной частной конфигурацией и точной документированной командой. Неизвестный процесс остаётся нетронутым, обновление сообщает неполную миграцию. Частные JSON не удаляются. Удаляются только три согласованных устаревших файла комплекта, включая обновление из самого установленного каталога; ошибка удаления видна.
- Аудит архива проверяет размер открытого файла и ограничивает чтение того же дескриптора, включая дополнительный байт при росте. Обычный архив читается непосредственно в буфер без второй полной копии. Ограничения ZIP/CRC/распаковки и запреты частных данных сохранены; `watcher-ready.json` добавлен в запреты.
- Средства запуска получают явный список шести публичных руководств, четырёх публичных изображений и основных файлов. Планы и материалы сопровождения не входят в ZIP. Подготовка выпуска выполняет также линтер и проверки границ импортов.
- Руководства обновлены с сохранением истории, авторства, лицензирования, ограничений платформ и защищённых подключений. `AGENTS.md` содержит весь обязательный набор; уникальных правил в прежнем `CLAUDE.md` не было, поэтому он нормализован до `@AGENTS.md`.

## Проверки и ограничения

Прочитаны существующие `test/launcher.test.ts`, `test/macos-launcher.test.ts`, `test/release-audit.test.ts`, `test/release-docs.test.ts`, владельцы средств запуска/упаковки и исторический Windows watcher. Новые проверки защищают наблюдаемые отказы обновления и упаковки; производственные экспортируемые швы для тестов не добавлены. Windows-фикстура исполняет извлечённые реальные функции PowerShell, подставляя только путь автоматического `$PSScriptRoot`, который теряется при извлечении AST; это не копия реализации на JavaScript.

Полный набор: чистая установка зависимостей, линтер, границы импортов, TypeScript, 207 успешных тестов из 209 (два пропуска Windows), проверка manifest/сборки, упаковка, подготовка локального выпуска `1.0.1`, аудит каталогов/готовых архивов и автономный runtime. Нативный переносимый PowerShell `7.6.6` на Mac подтвердил реальные функции и восемь проверок политики; он не подтверждает Windows PowerShell 5.1, CIM, COM, регистрацию автозапуска или Windows-приложение.

Сохранены причинные отрицательные проверки старых функций I2/I3/I4. Для архива 512 МиБ + 1 байт старая реализация достигла 574768 КиБ памяти, новая — 48128 КиБ и отвергла файл до чтения тела. Сжатый архив метода 8 принят, неверный CRC отвергнут. I5 подтверждён исполнением изолированной миграции и историческим исходником; реальный установленный SSH не проверялся.

На промежуточной проверке обнаружен отсутствующий импорт `spawnSync` в новом тесте и исправлен; финальные обязательные проверки проходят. Первая проба новой Mac-фикстуры потребовала ожидания завершения дочернего процесса; финальная версия также изолирует его команды и проверяет снятие блокировки перед удалением временного каталога.

Три независимые роли `ce-simplify-code` дали четыре применённых упрощения; результаты — `evidence/u8-simplification.json`. Применены также `test-audit` и правила `x9-context-files-generator`/`x9-agent-instructions`. Команды и контрольные суммы — `evidence/u8-validation.json`. Пакеты остаются в игнорируемых `dist/`, `release/`, `outputs/` и корневом `.streamDeckPlugin`; двоичные результаты не входят в изменение Git. Новые каталоги `$CODEX_HOME/evidence` и `$CODEX_HOME/worktrees` не создавались.

Живые Mac Codex/OpenCode/Fedora/`Both`, самостоятельный Windows и физическое устройство не проверены. Приёмочный сценарий с сохранённым профилем, собственным старым watcher, незатронутым OpenCode и физическими нажатиями находится в `u8-acceptance.md`; общая приёмка R1–R14 остаётся незавершённой до этих наблюдений. Переносимый PowerShell подготовил корневой исполнитель; его удаление также остаётся за ним.

Дополнение основного исполнителя: финальная проверка выявила и исправила случайное включение CLI при предварительном импорте Windows и устаревшее ожидание числа самотестов. Обе команды используют отдельный аргумент-заполнитель, фикстура собирает настоящий автономный runtime; причинная отрицательная и положительная пробы выполнены. Добавлены четыре ветви потребителя отметки готовности с подменённой границей процесса. Итоговые суммы пересобранных комплектов и проверки находятся в `evidence/final-owner-validation.json`, исторические суммы U8 относятся к более ранней сборке.

Ранний запуск дочерней Mac-фикстуры был недостаточно изолирован и мог обнаружить настоящее приложение. По сохранённому выводу невозможно доказать отсутствие воздействия. Исправленная версия блокирует все внешние команды дочернего процесса и подтверждает его выход/очистку; это не устраняет ретроспективное ограничение свидетельств. Подробная оговорка сохранена в `implementation-report.md`.
