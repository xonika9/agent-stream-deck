Mac разблокирован, переключение источников и обычные физические нажатия подтверждены. Подробности текущего состояния — `evidence/live-macos-20261005.json`; Windows явно отложен пользователем.

Метаданные приложений не являются приёмкой: OpenCode `2.0.22`, Stream Deck `7.6.0` (`23012`), CodexBar `0.70.0` (`161`). Исторически изученные OpenCode `2.0.5`/`2.0.10` не подтверждают новую версию. Ограниченный поиск стандартных каталогов не нашёл Codex; это не доказывает его отсутствие.

Не записывать адреса SSH, токены, личные пути, содержимое чатов и пользовательские профили в публичный отчёт. Общая приёмка R1–R14 остаётся незавершённой до наблюдаемого результата перечисленных живых сценариев и физического устройства.

Дополнение живой приёмки: обнаружен и проверен мост действующего Codex `26.930.31730` (сборка `12947`), bundle `com.openai.codex` в приложении ChatGPT. Приёмка интерфейса и физического устройства не завершена; ранние сведения о стандартных каталогах остаются историческим ограниченным поиском.

После ручной разблокировки настоящий интерфейс проверен: `OpenCode` даёт пустые слоты при отсутствии активных задач, `Codex` показывает карточку, исходный `Both` восстановлен и карточки возвращаются. Локальный OpenCode Desktop 2.0.22 запущен; сборщик видит Mac и Fedora, оба каталога `capacity-exceeded`, активных карточек нет. Кольцо контекста сохранено, локальный индикатор зелёный, квота отображается в приложении без сброса. Это не физическая проверка. Нужны нажатия пользователя, активные сценарии OpenCode и отключение/восстановление Fedora; Windows явно отложен пользователем.

Пользователь подтвердил два физических нажатия на Stream Deck MK.2: карточка текущего Codex открыла нужный чат, пустой слот ничего не сделал. Проверка удержания и изменения очереди ещё не выполнена. Прежнее ожидание переключения квоты по короткому нажатию было неверным: окно выбирается в настройках, обработчика нажатия у usage-limit нет. Новым явным решением пользователя платный сброс удаляется; старое назначение сохраняет только счётчик. Прежние требования приёмки платного сброса заменены проверкой невозможности списания.

Новое подтверждение пользователя: после запуска задачи OpenCode карточка появилась, стала зелёной, нажатие открыло приложение. Windows явно отложен пользователем, его приёмка/CI остаются открыты. Для OpenCode пока не подтверждены исчезновение просмотренной ревизии, повторное завершение в том же чате и восстановление Fedora.

Пользователь подтвердил: просмотренная карточка OpenCode исчезла, новая задача в том же чате вернула карточку. Ошибка уведомления API и новое зелёное завершение отдельно не проверены.

Потеря/восстановление реального SSH проверены в отдельном настоящем сборщике: только собственный туннель пробы остановлен, локальный источник доступен, новое соединение восстановлено, старые завершения не добавлены. Карточек во время этой пробы не было, поэтому сохранение активной локальной карточки в рабочем плагине не подтверждено. См. `evidence/fedora-reconnect-20261005.json`.
