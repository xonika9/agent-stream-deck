Локальные сборки находятся в `outputs/release-v1.0.1/`; перед установкой проверить `SHA256SUMS.txt` из этого каталога. После отдельного разрешения пользователя обновлён наблюдатель и перезапущен плагин из существующей ссылки на проверенную сборку. Профили сохранены. Интерфейсная проверка остановлена до ручной разблокировки Mac. Подробности текущего состояния — `evidence/live-macos-20261005.json`; Windows недоступен.

Метаданные приложений не являются приёмкой: OpenCode `2.0.22`, Stream Deck `7.6.0` (`23012`), CodexBar `0.70.0` (`161`). Исторически изученные OpenCode `2.0.5`/`2.0.10` не подтверждают новую версию. Ограниченный поиск стандартных каталогов не нашёл Codex; это не доказывает его отсутствие.

Не записывать адреса SSH, токены, личные пути, содержимое чатов и пользовательские профили в публичный отчёт. Общая приёмка R1–R14 остаётся незавершённой до наблюдаемого результата перечисленных живых сценариев и физического устройства.

Дополнение живой приёмки: обнаружен и проверен мост действующего Codex `26.930.31730` (сборка `12947`), bundle `com.openai.codex` в приложении ChatGPT. Приёмка интерфейса и физического устройства не завершена; ранние сведения о стандартных каталогах остаются историческим ограниченным поиском.

После ручной разблокировки настоящий интерфейс проверен: `OpenCode` даёт пустые слоты при отсутствии активных задач, `Codex` показывает карточку, исходный `Both` восстановлен и карточки возвращаются. Локальный OpenCode Desktop 2.0.22 запущен; сборщик видит Mac и Fedora, оба каталога `capacity-exceeded`, активных карточек нет. Кольцо контекста сохранено, локальный индикатор зелёный, квота отображается в приложении без сброса. Это не физическая проверка. Нужны нажатия пользователя, активные сценарии OpenCode и отключение/восстановление Fedora; Windows недоступен.

Пользователь подтвердил два физических нажатия на Stream Deck MK.2: карточка текущего Codex открыла нужный чат, пустой слот ничего не сделал. Проверка удержания и изменения очереди ещё не выполнена. Прежнее ожидание переключения квоты по короткому нажатию было неверным: окно выбирается в настройках, обработчика нажатия у usage-limit нет. Новым явным решением пользователя платный сброс удаляется; старое назначение сохраняет только счётчик. Прежние требования приёмки платного сброса заменены проверкой невозможности списания.
